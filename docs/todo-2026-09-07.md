## Related open items (from 2026-09-06 debugging)

### A. Unprotected seller auth endpoints in production
`src/routes/auth.ts` — no `NODE_ENV` guard, no rate limit, no verify-attempt cap, live on the
deployed backend:
- `POST /api/v1/auth/seller/send-otp`
- `POST /api/v1/auth/seller/verify-otp` — issues a 30-day seller JWT on a correct 6-digit code
- `POST /api/v1/auth/seller/login` — issues a seller JWT with **no OTP at all** ("legacy testing")

The app only calls these when `__DEV__` is true and Firebase fails. Risk: brute-force
`verify-otp` (1,000,000 combos, no SMS needed) → account takeover; or just use `/seller/login`.
Rate-limiting plan was dropped — Firebase protects the real OTP path. **Fix:** gate all three
behind `if (env.NODE_ENV === 'production') return 404` and delete `/seller/login`. Decision pending.

### B. JWT secret mismatch — LOCAL gateway/user-service are wrong, not this repo
Confirmed 2026-09-07 by decoding a live Firebase-login token: prod user-service (the real issuer)
signs with **`9f7c3a2b…`**, and this QC backend already verifies with `9f7c3a2b…` — they agree.
The **local** `EH-api-gateway/.env` + `extrahand-user-service/.env` use a *different* value
(`R9mA4ZQe…`), so a real prod token is 401'd by the local gateway.
**Fix:** set `ACCESS_TOKEN_SECRET=9f7c3a2b6e8d4a1f9e2c7b5d1a6f8c0e3b4d9a7f2e6c5d8b1a4e9c7f2d6`
in `EH-api-gateway/.env` **and** `extrahand-user-service/.env`, restart both. Do NOT touch this repo.
(Verified: with the local gateway on `9f7c3a2b…` the app's existing token authenticated and the
full notification pipeline worked end-to-end.)
